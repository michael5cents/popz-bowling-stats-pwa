# Public Bowling v39.022 - repaired iPad QA shortcut that lost telemetry exclusion

Date: 2026-11-19.

## Incident
Owner installed a Popz QA shortcut from Chrome on a physical iPad. The original query QA URL showed the telemetry-off badge, but the icon opened without it. A query-string-dependent PWA start_url was not reliably preserved. Do not score from this unverified old shortcut.

## Fix
- New permanent owner-only QA address: https://popzbowling.com/qa-ipad/ (no query parameters). Create a NEW Home Screen shortcut from this path.
- The strict dist allowlist build generates a dedicated QA HTML page from the current root app shell, with base href /, noindex, static link to /qa-tablet.webmanifest, QA page title and Apple Home Screen label. These settings are present BEFORE any JavaScript executes.
- The separate QA manifest uses id /qa-ipad/, start_url /qa-ipad/, scope /qa-ipad/ and display standalone; the regular customer PWA manifest and identity remain unchanged.
- Entry, main app, adoption telemetry client and runtime-monitor all detect the /qa-ipad/ pathname, even if iPad Chrome discards query strings. QA badge remains visible, full tablet layout is forced, and no adoption/runtime event is queued or sent. Synthetic series have permanent _telemetry.eligible=false to block later milestone backfill.
- Service worker precaches a separate QA shell, and keeps offline QA navigation cache separate from the normal customer shell. QA path is no-store and blocked from search indexing.
- Original query QA link remains for older browser simulators, not for installing an iPad shortcut. The owner must verify the badge on actual iPad after creating the NEW shortcut.

## Test and deployment constraints
- All 62 Node tests, Pages Functions compilation, Chrome+Safari tablet browser QA and REAL offline service-worker browser simulation must pass.
- Tests cover zero-query QA launch, correct manifest and badge, persisted ineligible scoring series, zero telemetry/runtime POSTs, no console errors, offline reload, and no cache pollution of normal public root.
- Only dist/ allowlist may be deployed; do not modify D1 telemetry, customer Stripe, Firebase or real scoring history. Do not touch existing uncommitted tools/launch-qa-phone.sh on MacBook.
- Release source, live health, URL and documentation should be verified after deployment. Real iPad icon behavior cannot be certified without owner observation.
