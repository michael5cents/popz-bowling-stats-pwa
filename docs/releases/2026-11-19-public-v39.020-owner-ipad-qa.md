# Public Bowling v39.020 - owner iPad QA PWA

2026-11-19. Production public app https://popzbowling.com/, distinct from Personal Bowling at popzplace.com.

## Request and reviewed sources
The owner wants to test the public app on their iPad without polluting customer telemetry. Reviewed MacBook canonical public repo, matching GitHub and Gitea main, Collective public-bowling project, Obsidian Bowling public commercialization notes, generated Wiki pages, telemetry access runbook and commercial releases.

## Issue / fix
Existing ?qa=1&tablet=1 bypassed browser installation gate, forced Full Layout, suppressed both adoption and runtime telemetry and stamped new bowling series with _telemetry.eligible=false to prevent retrospective scoring milestone backfill. However the regular PWA manifest start_url was ./, so the iPad home-screen icon might relaunch without qa=1.
On the exact owner QA URL https://popzbowling.com/?qa=1&tablet=1, entry.js now selects a separate qa-tablet.webmanifest with id /qa-tablet, start_url /?qa=1&tablet=1, scope /, standalone, name Popz Bowling QA - iPad and label Popz QA. The normal customer manifest stays unchanged. A visible OWNER QA - TELEMETRY OFF badge in the header and QA - telemetry off label in Settings confirm suppressed status. The static manifest is explicitly allowlisted in dist/ and pre-cached for offline install.
The new QA path still exercises current production bowling code. It does not bypass the Stripe entitlement logic, and it does not sandbox Google Sync or Live Scores. An eligible new installation receives the standard 30-day Pro trial. Avoid live Stripe checkout: it is a real payment. Stay signed out of Google Sync, or use a separate testing Google account so synthetic games never merge with real user data.

## iPad owner install
Open the exact QA URL above in Safari. Confirm OWNER QA - TELEMETRY OFF is visible on page. Tap Share, Add to Home Screen, enable Open as Web App if shown, name the icon Popz QA, tap Add. Launch the icon and confirm the QA badge is still visible before recording any test rolls. Browser start_url is a hint and some older iPadOS versions may vary; never continue testing without verifying the QA badge. If missing, use the original exact QA URL in Safari, not the plain customer URL.
Once installed, ordinary app updates and offline scoring work via the existing PWA worker. Reopen online once before testing offline.
QA mode is for internal evaluation only. Feedback, paid checkout, cloud sync, and live sharing may interact with real third-party systems; this exclusion is specifically for adoption and runtime telemetry.
